# Tempora Mail

A Next.js App Router starter for disposable inboxes, with Resend inbound email, Supabase storage, expiry/deletion, and a mobile-friendly UI.

**Real email delivery is not active just because this repository is deployed.** Configure a domain Resend can receive mail for, set its DNS records, configure the webhook, and add the server secrets below.

## Architecture
- Next.js on Vercel: UI and API routes.
- Resend Receiving: receives email and posts `email.received` events to `/api/webhooks/resend`.
- Supabase Postgres: stores inbox metadata and message bodies.
- A random browser token is returned once at inbox creation; APIs require it in `x-inbox-token`. Only its SHA-256 hash is stored.
- Expiry is enforced by API routes; Vercel Cron deletes expired inboxes and their messages hourly.

This is a starter, not a guarantee of anonymity or perfect privacy. Avoid sensitive accounts. Email HTML is shown as untrusted text and never injected into the page.

## 1. Create the database
1. Create a Supabase project.
2. Run `supabase/schema.sql` in its SQL Editor.
3. Copy the project URL and service-role key from Project Settings → API. Never prefix the service-role key with `NEXT_PUBLIC_`.

## 2. Configure Resend receiving
1. Configure a domain or receiving subdomain you control in Resend, such as `mail.example.com`.
2. Add the exact MX/DNS records shown by Resend.
3. Set `MAIL_DOMAIN` to that receiving domain.
4. Create a Resend webhook for `email.received` pointing to `https://YOUR-VERCEL-DOMAIN/api/webhooks/resend`.
5. Put its signing secret in `RESEND_WEBHOOK_SECRET`.
6. Send a test email to an address generated by the deployed app.

Resend's event includes metadata; the app uses its Receiving API to fetch the actual message body before saving it.

## 3. Deploy
1. In Vercel, import this repository.
2. Set the project Root Directory to `tempora-mail`.
3. Add all values from `.env.example` under Project → Settings → Environment Variables.
4. Deploy, then configure the Resend webhook with the final Vercel URL.
5. Test with an email sent from another account; check Resend webhook logs and Vercel function logs if it doesn't arrive.

For local development, copy `.env.example` to `.env.local`, fill values, run `npm install` and `npm run dev`. A public HTTPS tunnel is required for local inbound webhook testing.

## Environment variables
| Name | Required | Description |
|---|---|---|
| `SUPABASE_URL` | Yes | Supabase project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | Yes | Server-only Supabase service-role key |
| `RESEND_API_KEY` | Yes | Resend API key with receiving API access |
| `RESEND_WEBHOOK_SECRET` | Yes | Signing secret for the inbound webhook |
| `MAIL_DOMAIN` | Yes | Configured receiving domain, without `@` |
| `CRON_SECRET` | Yes | Long random secret for cleanup |
| `INBOX_TTL_MINUTES` | No | Inbox lifetime, default 60 minutes |

## API
- `POST /api/inboxes` — create inbox; returns address, token, expiry.
- `GET /api/inboxes/:id/messages` — list messages; requires `x-inbox-token`.
- `GET /api/inboxes/:id/messages/:messageId` — read one message.
- `DELETE /api/inboxes/:id` — delete inbox and messages.
- `POST /api/webhooks/resend` — signed inbound webhook.
- `GET /api/cron/cleanup` — delete expired inboxes; requires `Authorization: Bearer $CRON_SECRET`.

## Before public launch
- Add distributed rate limiting, CAPTCHA or per-IP creation limits, provider quotas and abuse monitoring.
- Review privacy/data protection obligations, retention policy, backups and incident handling.
- Attachments are not supported by this starter.
- Check Resend's current inbound-domain and plan limits.
- Public disposable email can be abused and blocked by other services.

Treat the inbox token like a password. Expired inboxes become inaccessible immediately, while physical cleanup runs hourly.
